
# QA Testing Knowledge Base – Quick Guide

## 1. Introduction to QA

QA (Quality Assurance) to proces zapewniania jakości oprogramowania. Jego celem jest wykrywanie błędów i sprawdzanie, czy aplikacja działa zgodnie z wymaganiami.

## 2. Main Types of Testing

- Functional Testing – sprawdzanie funkcjonalności strony.
- UI Testing – sprawdzanie wyglądu interfejsu.
- UX Testing – ocena wygody użytkowania.
- Performance Testing – sprawdzanie wydajności.
- Security Testing – sprawdzanie bezpieczeństwa.
- Responsive Testing – sprawdzanie działania na różnych urządzeniach.
- Accessibility Testing – sprawdzanie dostępności.

## 3. Testing Process

1. Analiza wymagań.
2. Przygotowanie planu testów.
3. Tworzenie checklist i test cases.
4. Wykonywanie testów.
5. Zgłaszanie błędów.
6. Ponowne testowanie.
7. Przygotowanie raportu.

## 4. How to Use Checklists

Checklist to lista kontrolna zawierająca elementy, które należy sprawdzić podczas testowania strony internetowej.

Podstawowe przykłady:
- Sprawdzenie strony głównej.
- Sprawdzenie menu.
- Testowanie formularzy.
- Sprawdzenie linków.
- Testowanie responsywności.

## 5. Test Case

Test Case to opis konkretnego scenariusza testowego.

Powinien zawierać:
- ID testu.
- Nazwę testu.
- Warunki wstępne.
- Kroki testowe.
- Oczekiwany rezultat.
- Rzeczywisty rezultat.
- Status.

## 6. Bug Report

Bug Report to dokument opisujący znaleziony błąd.

Powinien zawierać:
- ID błędu.
- Tytuł.
- Opis problemu.
- Kroki odtworzenia.
- Oczekiwany rezultat.
- Rzeczywisty rezultat.
- Priorytet i ważność błędu.

## 7. Test Statuses

- PASS – test zakończony poprawnie.
- FAIL – test zakończony niepowodzeniem.
- BLOCKED – test nie może zostać wykonany.
- NOT TESTED – test nie został wykonany.

## 8. Useful Tools

- Google Lighthouse – analiza wydajności i jakości strony.
- Chrome DevTools – analiza i diagnostyka strony.
- WAVE – sprawdzanie dostępności.
- Postman – testowanie API.
- GitHub – przechowywanie dokumentacji i zarządzanie projektem.
