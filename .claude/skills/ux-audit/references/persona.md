# Persona i ścieżka

Persona opisuje konkretną osobę z celem i ograniczeniami, które zmieniają sposób korzystania ze strony. Opieraj ją na danych o odbiorcach. Jeśli ich nie ma, nazwij ją personą roboczą ([NN/g: persony](https://www.nngroup.com/articles/persona/), [W3C: historie użytkowników](https://www.w3.org/WAI/people-use-web/user-stories/)).

## Pola

| Pole w plan.json | Co wpisać |
|---|---|
| `name`, `age`, `role` | imię, wiek, zajęcie |
| `quote` | jedno zdanie o nastawieniu |
| `bio` | sytuacja życiowa istotna dla zadania, 3–5 zdań |
| `tech` | urządzenia, łącze, biegłość, technologie wspomagające |
| `goals` | 2–4 cele |
| `needs` | czego potrzebuje, żeby zadanie się udało |
| `frustrations` | co ją zatrzymuje |
| `scenario` | zadanie bez nazw przycisków ([NN/g: scenariusze](https://www.nngroup.com/articles/task-scenarios-usability-testing/)) |

Dobra persona audytowa ma co najmniej jedno ograniczenie trwałe, chwilowe lub sytuacyjne (np. ADHD, dysleksja, słaby wzrok, jedna ręka zajęta, telefon w autobusie). Unikaj stereotypów i cech, które nic nie zmieniają.
